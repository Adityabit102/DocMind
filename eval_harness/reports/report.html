On clean images the layout-aware engine underperforms the raw-OCR baseline: field accuracy 0.99 → 0.94 (-0.05). The degradation charts show where the gap widens under blur/skew/low-resolution — the actual point of the 'OCR enhancement' claim.

At max severity the layout-aware engine is more robust on: pixel_noise (0.00→0.12). It trails on: rotate (0.20→0.12). This is the accuracy/robustness trade-off the degradation curves exist to expose — a single clean number would have hidden it.

Donut VLM — ZERO-SHOT (evaluated, not fine-tuned): field accuracy 0.00. Reported as-is. Donut here is donut-base-finetuned-cord-v2, pretrained on the CORD receipt schema, so it emits receipt tags rather than this form’s keys, e.g.:
<s_menu><s_nm> INVOICE</s_nm><s_discountprice> -52445</s_discountprice><s_price> 2026-03-13</s_price> … <s_total_price> $8829.12</s_total_price>
A diagnostic (vlm_module/donut_diagnostic.py) shows raw value recall 0.65 vs. schema-aligned accuracy 0.00: Donut’s OCR reads most values but assigns none to the right field. This is a schema-mismatch failure, not an OCR failure and not a broken eval (the same harness scores the OCR engines 0.99 / 0.94).

Donut VLM — LoRA FINE-TUNED on this schema: field accuracy 0.99 (up from 0.00 zero-shot). Genuinely closing “VLM adapted”: LoRA on the decoder’s attention projections (524,288 trainable params = 0.26%), 90 training forms rendered from a different seed than every eval image here — zero overlap — 3 epochs, loss 1.19→0.011 in 423s CPU (vlm_module/train_donut_lora.py). On a separate, larger same-template comparison (24 held-out images) this reached 0.993 field accuracy, matching the strongest OCR baseline exactly. Caveat: train/eval images share one rendering template (only field values differ) — this demonstrates the adaptation mechanism, not generalization to visually different real-world layouts.
