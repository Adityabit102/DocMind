On clean images the layout-aware engine underperforms the raw-OCR baseline: field accuracy 0.99 → 0.89 (-0.10). The degradation charts show where the gap widens under blur/skew/low-resolution — the actual point of the 'OCR enhancement' claim.

At max severity the layout-aware engine is more robust on: pixel_noise (0.00→0.31). This is the accuracy/robustness trade-off the degradation curves exist to expose — a single clean number would have hidden it.

Donut VLM — ZERO-SHOT (evaluated, not fine-tuned): field accuracy 0.00. Reported as-is. Donut here is donut-base-finetuned-cord-v2, pretrained on the CORD receipt schema, so it emits receipt tags rather than this form’s keys, e.g.:

A diagnostic (vlm_module/donut_diagnostic.py) shows raw value recall 0.65 vs. schema-aligned accuracy 0.00: Donut’s OCR reads most values but assigns none to the right field. This is a schema-mismatch failure, not an OCR failure and not a broken eval (the same harness scores the OCR engines 0.99 / 0.89). Genuinely closing “VLM adapted” would require LoRA-fine-tuning Donut on this schema — not done here.
